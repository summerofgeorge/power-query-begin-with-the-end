# Begin with the end: Power Query and Copilot

A fictional branch-sales exercise from Stringfest Analytics. Sales are in USD.

## Files

- `begin-with-the-end.xlsx`: two raw Excel tables and a static prepared target for the same inputs. The starter deliberately contains no Power Query query.
- `prompts.txt`: plan, build, M-code fallback, and handoff prompts.
- `ReportedSales.pq`: the Power Query M implementation generated by Copilot during the example, retained for inspection and practice.

## Follow along

1. Open a copy of the workbook in Excel for Microsoft 365 on Windows. Open Copilot and send the plan prompt from `prompts.txt`. If your Copilot surface offers a Get Data skill, select it; availability varies by account and surface.
2. Review the proposed rules, then send the build prompt. If Copilot cannot save a query, use the M-code prompt and install the code as described below. Check that a saved query exists under Data > Queries & Connections.
3. Compare the output against `TargetExample` by Region, Branch, SKU, and Date. Row order is not significant.
4. Perform the refresh checks below without asking Copilot to regenerate the query.

To install generated M in Excel for Windows, choose Data > Get Data > From Other Sources > Blank Query. In Power Query Editor, open Home > Advanced Editor, replace the code with the complete M query, name the query `ReportedSales`, and choose Close & Load > Close & Load To... Select Table and New worksheet, leave Add this data to the Data Model unchecked, and click OK. If it has already loaded, right-click the query in Queries & Connections and choose Load To... to set this destination. You can use the supplied `ReportedSales.pq` to practice without Copilot. The ribbon's Get Data command and Copilot's Get Data skill are different entry points.

The observed Copilot session in Excel for the web did not have the Get Data skill enabled; it generated M code instead. Excel desktop is the primary environment for inspecting the code and doing the refresh checks in this exercise. If Copilot requires cloud storage in your account, save your working copy in your organization's approved OneDrive or SharePoint location.

## Rules and expected baseline

Fill Branch down within each source table. Keep RowType = Detail. Split Product at ` | `, preserving SKU as text. Unpivot all date columns and append the regional results. Exclude missing amounts from this *reported-sales* output; retain numeric zero. Never use TargetExample as the query's input. The example holds no history beyond the supplied week.

Expected: **57 rows, $8,005 total, two zero-sales rows, three excluded missing amounts, zero duplicate Region/Branch/SKU/Date keys.** There are 12 detail rows and five date columns: 60 potential observations minus three missing amounts.

| Region | Branch | Expected sales |
|---|---|---:|
| East | Cleveland | 2,050 |
| East | Pittsburgh | 1,920 |
| West | Columbus | 2,400 |
| West | Cincinnati | 1,635 |

Missing amounts: Cleveland / 014 / 2026-11-05; Pittsburgh / 014 / 2026-11-04; Cincinnati / 027 / 2026-11-05. Zero amounts: Cleveland / 001 / 2026-11-04; Cincinnati / 014 / 2026-11-03.

## Refresh checks

Run each check on a fresh copy or restore the prior source before the next check. Keep the target example unchanged.

1. Change Raw_East!C2 from 120 to 145. Refresh. Expect 57 rows and $8,030, with Cleveland / 001 / 2026-11-02 = 145. Restore 120 and refresh again.
2. Add a column to BOTH raw Excel tables. Format its header cell as Text, then enter `2026-11-07` exactly. Verify the formula bar still shows that ISO text, not a regional date such as `11/7/2026`. Enter 10 in each of the 12 Detail rows and 30 in each of the four Subtotal rows. Refresh. Expect 69 rows and $8,125. Ensure the new column is inside each table. Subtotals must not be counted. Remove the added columns to restore the baseline.
3. Insert a Detail row in Raw_East's Cleveland block, before its subtotal. Use a blank Branch, Product `099 | Binder clips`, five amounts of 10, and RowType `Detail`. Ensure it is inside the Excel table. Refresh. Expect 62 rows and $8,055, with five new Cleveland / 099 records. Restore the baseline afterward.
4. On a separate copy, change Raw_East!C2 to `check`. Refresh should expose a conversion error. Do not silently turn that text into zero. A failed refresh can leave the previous loaded table on screen: inspect refresh status before using it.

The static target applies only to the original inputs. A matching total is not a complete comparison: also check the key set, amounts, types, blank exclusions, and zeros.

## Handoff

Keep the workbook with its saved query and both named source tables. Refresh reruns its stored M logic. Replace the source table contents carefully, resize tables as needed, and refresh; old rows left inside a table remain inputs. Overwriting this week's data does not retain prior weeks. A historical folder/SharePoint source is a separate design choice.

This reference expects Branch, Product, RowType, and date-named amount columns, with each branch's first row labeled. New table names, malformed product labels, missing branch labels, unexpected RowType values, duplicate keys, and new non-date columns need review. Source schema changes are not automatically safe just because refresh runs. For an external-source adaptation, document the location and permissions, and have the recipient test refresh under their own account.

Choose the rule once, inspect it, and let Power Query apply it again.
